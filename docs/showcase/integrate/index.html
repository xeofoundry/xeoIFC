Build on xeoIFC

xeoIFC is one IFC engine with the same functions in the browser (WebAssembly with a WebGPU viewer) and in native programs (one plain C header). It reads IFC 2x3 to IFC 4.3, tessellates it, answers queries, and writes IFC for splits, merges and authored models. This page is for developers who want xeoIFC inside their own product: which platforms exist today, a small working program for each, and how evaluation and licences work.

3. The same API everywhere

The browser library, the native library and the command line share one document API: JSON operations in, JSON results out. The query of the samples is the same request in every language:

{"op": "query.select", "doc": "m",
 "args": {"text": "is IfcWall and Pset_WallCommon.IsExternal = true",
          "select": ["name", "storey.Name"], "includeRefs": true}}

The command line prints the whole API as TypeScript declarations: xeoifc describe.

4. Evaluation and licences

Every function works without a licence key; viewing is free. Without a key, each IFC file that the library writes carries one more element, an IfcBuildingElementProxy with the text "xeoIFC evaluation version", and the converter marks its GLB and XKT files the same way. A licence key removes the marker:

xeoifc_set_licence_key(session, key, NULL);        /* C: 1 licensed, 0 no key, -1 unknown or expired */
worker_set_licence_key(key, Date.now() / 1000);    // browser (Web Worker)
xeoifc -i model.ifc -o model.glb --license-key KEY # command line, or XEO_IFC_LICENSE_KEY
